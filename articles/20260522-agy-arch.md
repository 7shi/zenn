Gemini CLI の後継である [Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) を使用する際、Arch Linux (WSL2) で認証情報を保存する方法について説明します。

:::message
seahorse の操作自体は Arch Linux に依存していないので、他の Linux ディストリビューションでも同様の手順で認証情報を保存できると思います。
:::

## 現象

Antigravity CLI を起動するたびに、毎回 OAuth 認証を要求されるので困っていました。

にょせがわさんから、Linux/WSL 環境の場合、Secret Service をインストールする必要があると教えていただきました。👉[参考](https://x.com/nyosegawa/status/2057481590922731910)

WSL2 で GNOME は使用していなかったため、インストールしていない状況でした。

## GNOME keyring

GNOME keyring と管理ツールの seahorse をインストールします。

```sh
sudo pacman -S gnome-keyring seahorse
```

インストール後、seahorse を起動して、デフォルトのキーリングを作成します。

左上の [+] ボタンをクリックして、"パスワードキーリング" を選択します。

![seahorse1.png](/images/20260522-agy-arch/seahorse1.png)

キーリングの名前（特に決まりはないようで、任意に設定可能）を入力して [追加] ボタンをクリックします。

![seahorse2.png](/images/20260522-agy-arch/seahorse2.png)

キーリングのパスワード（ユーザーのパスワードとは別で、任意に設定可能）を 2 回入力して [Continue] ボタンをクリックします。

![seahorse3.png](/images/20260522-agy-arch/seahorse3.png)

作成されたキーリングを右クリックして、「デフォルトにする」を選択します。

![seahorse4.png](/images/20260522-agy-arch/seahorse4.png)

以上で準備完了です。

Antigravity CLI を起動して OAuth 認証を行うと、認証情報が保存されるはずです。

![seahorse5.png](/images/20260522-agy-arch/seahorse5.png)

次回以降の Antigravity CLI 起動時には、この認証情報が使用されます。
